# 学習ガイド（TypeScript / Flutter / 最先端 AI 開発）

このプロジェクトを教材に、TypeScript・Flutter/Dart・最先端の AI 開発（Claude Code のエージェント／ワークフロー／レビュー自動化）を学ぶためのガイド。読者の背景は **PHP / Laravel / HTML / CSS / JS 3年**。

> 前提の方針：新しい本を別でやるより、**いま動いている PR・レビュー・コミット解説を毎回読み込む**のが最短。Laravel という既知の土台から橋渡しして理解する。

---

## 大原則：このプロジェクトを「教材」にする

毎 PR で次のループを習慣化する。

1. **diff を自分で読む**（何が変わったか）
2. **コミット解説を読む**（概要／Laravel 対比／TS・Flutter 特有／注意点）
3. **レビュー指摘で答え合わせ**（5観点レビューが"先生"。なぜ NG かを学ぶ）

この3ステップだけで、実コードに紐づいた知識が定着する。

理由：
- 実装に紐づくので忘れにくい
- 5観点レビューが間違いを指摘してくれる
- 既知（Laravel/JS）からの差分で覚えられる

---

## ① TypeScript（最優先・進行中）

JS 経験があるので **型システムだけ**に集中すれば最短。

**今のコードで学べる順番**
1. `interface` / `type`（例: `UserRow`・`TokenResponse`）＝ 型宣言。PHP のクラス/DTO の感覚
2. `unknown` と絞り込み（例: `req.body` の検証、`err instanceof Error`）＝ **PHP/JS と最も違う点**。「型が不明な値は使う前に絞る」
3. ジェネリクス（例: `query<UserRow>(...)`・`Promise<T>`）
4. strict 系フラグ（`noUncheckedIndexedAccess` で `arr[0]` が `T | undefined` になる 等）

**やること**：各ファイルの型注釈を「なぜこの型か」言えるか自問。分からなければ質問する。

**資料**：公式 TypeScript Handbook の "Everyday Types" と "Narrowing" の2章を先に。残りは必要時。

**JS 経験者がハマる落とし穴**
- `any` で逃げる癖／`as` の乱用（型安全を捨てている）
- ESM の相対 import に `.js` 拡張子が必要（nodenext）
- `verbatimModuleSyntax`：型だけの import は `import type` を使う

## ② Flutter / Dart（mobile フェーズで本格化）

バックエンドが固まったら着手。それまでの助走。

- **Dart は「型付き JS ＋クラス」**くらいの距離感。TS を先にやると Dart の型はスッと入る（順番が良い）。
- **UI は宣言的**（React に近い）。HTML/CSS 経験が活き、`build()` が render に相当。Blade のような「テンプレ＋ロジック」とは違い、**UI をコードで組む**。
- **今やれる助走**：`flutter run -d web-server` で動く雛形（`mobile/lib/`）のカウンターアプリを 1 行ずつ改造（ボタン追加・状態を増やす）。"Widget = 部品の入れ子" の感覚を掴む。
- mobile 着手時に、API クライアント・状態管理・画面遷移を Laravel/JS と対比しながら解説する。

## ③ 最先端 AI 開発（このハーネス自体が教材）

いま運用している仕組みそのものを読み解く。

**理解すべき4層（すべて稼働中）**
1. **CLAUDE.md** … プロジェクトの共有知識（全 AI が最初に読む土台）
2. **エージェント**（`.claude/agents/` の5観点レビュアー）… 役割特化の分身
3. **ワークフロー**（設計理解フェーズで使った並列オーケストレーション）… 多エージェントを決定論的に回す
4. **CI 連携**（claude-code-action の `@claude /review-pr`）… レビュー自動化＋**収束（自動 baseline）**

**やること**：`.claude/` 配下を読み「なぜこの設計か」を追う。特に `review-pr.md` の収束ロジック（増分再レビュー・reuse 検知）は AI ワークフロー設計の良い実例。

**この先の山場**：予約 CRUD 以降で、実装をワークフローで並列化する場面が来る。そこで「単発エージェント vs ワークフロー」の判断基準を体得する。
